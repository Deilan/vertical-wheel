# ТЗ v0.1: веб-приложение «Вертикальный барабан»

## 1. Цель

Сделать одностраничное веб-приложение без бэкенда, где пользователь может:

1. Крутить вертикальный барабан жестом drag/swipe.
2. Получать выпавший результат.
3. Создавать и редактировать свой барабан.
4. Делиться барабаном через ссылку.
5. Импортировать/экспортировать полный JSON-конфиг.

Основной приоритет — корректная работа на мобильных устройствах iOS и Android. Desktop вторичен.

# 2. Стек

Рекомендуемый стек:

```txt
React
TypeScript
Vite
CSS Modules
lz-string
idb
Vitest
```

Назначение:

* `React` — компоненты и состояние.
* `TypeScript` — типизация конфигов и алгоритмов.
* `Vite` — сборка.
* `CSS Modules` — изоляция стилей.
* `lz-string` — сжатие конфигурации для share-ссылки.
* `idb` — хранение полного локального конфига с картинками в IndexedDB.
* `Vitest` — тесты для чистых функций.

Приложение должно собираться как static SPA:

```bash
npm run build
```

Без серверных API.

# 3. Основные режимы

## 3.1 Spin mode

Основной режим, открывается по умолчанию.

На экране:

* заголовок барабана, необязательный;
* описание, необязательное;
* вертикальный барабан;
* фиксированная стрелка/указатель;
* последний результат;
* раскрываемая история последних результатов;
* кнопка «Редактировать».

Кнопки «Скопировать ссылку», «Импорт JSON», «Экспорт JSON» находятся в edit mode.

## 3.2 Edit mode

Редактор барабана.

Требования:

* WYSIWYG-превью барабана;
* изменения сразу видны в превью;
* можно добавлять, удалять и переупорядочивать опции;
* можно редактировать title, subtitle, emoji, image, цвета;
* можно настраивать размеры карточек;
* можно настраивать тему, фон, цвет стрелки;
* можно скопировать share-ссылку;
* можно импортировать JSON;
* можно экспортировать JSON.

# 4. Визуальная модель барабана

Барабан — не 3D-цилиндр, а вертикальная циклическая лента карточек, как в прототипе.

Поведение:

* стрелка фиксирована;
* двигается лента;
* карточки повторяются циклически;
* если опций мало, список дублируется, чтобы заполнить экран;
* активная карточка определяется по положению относительно стрелки;
* после остановки центр выигравшей карточки должен совпадать с линией стрелки.

Выигравшая опция:

```ts
Winning option = option whose card center is aligned with the pointer line after final snap.
```

---

# 5. Управление жестом

В первой версии нет кнопки «Крутить». Только drag/swipe.

Жесты:

* свайп вверх;
* свайп вниз;
* мышь на desktop;
* touch/pointer на mobile.

Технические требования:

* использовать Pointer Events;
* для области барабана задать `touch-action: none`;
* страница не должна скроллиться во время свайпа по барабану;
* пока барабан вращается, новые жесты игнорируются.

---

# 6. Физика вращения

## 6.1 Слабый жест

Если жест не прошёл порог:

```txt
dragDistance < 40px OR releaseVelocity < 350px/s
```

то:

* лента во время жеста двигается за пальцем;
* после отпускания лента мягко доводится до ближайшей карточки;
* результат не засчитывается;
* история не обновляется.

## 6.2 Нормальный жест

Если жест прошёл порог:

```txt
dragDistance >= 40px AND releaseVelocity >= 350px/s
```

то запускается spin.

Требования:

* направление свайпа влияет на направление вращения;
* сила жеста влияет на дальность вращения;
* слишком сильный жест незаметно ограничивается;
* пользователь не может влиять на результат после запуска вращения;
* добавляется очень небольшая случайная поправка, чтобы не было лёгкого прицеливания;
* строгая равновероятность не требуется.

Начальные параметры:

```ts
minDragDistancePx = 40
minReleaseVelocityPxPerSec = 350
minSpinDurationMs = 1200
maxSpinDurationMs = 4500
maxVirtualCardsToTravel = 45
randomJitterCards = примерно до ±0.5 карточки
```

Финальный алгоритм:

1. Пользователь тянет ленту.
2. При отпускании считаются дистанция и скорость.
3. Проверяется порог запуска.
4. Если жест слабый — snap к ближайшей карточке без результата.
5. Если жест нормальный — рассчитывается физическая дальность.
6. Дальность ограничивается сверху.
7. Добавляется небольшой random jitter.
8. Финальная позиция округляется до центра ближайшей карточки.
9. Лента анимируется до финальной позиции.
10. Результат сохраняется в историю.

# 7. Модель данных

## 7.1 Wheel config

```ts
type WheelConfig = {
  version: 1;
  wheel: {
    id: string;
    title?: string;
    description?: string;
    settings: WheelSettings;
    options: WheelOption[];
  };
};
```

## 7.2 Wheel settings

```ts
type WheelSettings = {
  theme: "dark" | "light";

  appBackgroundColor: string;
  pointerColor: string;

  cardHeightPx: number;
  cardGapPx: number;
  imageSizePx: number;
  titleFontSizePx: number;
  subtitleFontSizePx: number;
  cardBorderRadiusPx: number;
};
```

Начальные диапазоны:

```ts
cardHeightPx: 88–220
cardGapPx: 8–32
imageSizePx: 40–120
titleFontSizePx: 16–36
subtitleFontSizePx: 12–24
cardBorderRadiusPx: 8–32
```

В редакторе каждый параметр меняется через ползунок и числовое поле. Ползунок влияет на число, число влияет на ползунок.

## 7.3 Wheel option

```ts
type WheelOption = {
  id: string;
  title: string;
  subtitle?: string;
  emoji?: string;
  image?: {
    kind: "url" | "data";
    value: string;
  };
  backgroundColor: string;
  textColor: string;
};
```

Правила:

* `title` обязателен;
* `subtitle` необязателен;
* Unicode должен поддерживаться корректно: кириллица, emoji, спецсимволы;
* если есть image — показывать image;
* если image нет, но есть emoji — показывать emoji;
* если нет ни image, ни emoji — показывать стандартную заглушку;
* layout карточки: слева зона картинки/emoji, справа title/subtitle;
* title максимум 2 строки;
* subtitle максимум 2 строки;
* если текст не влезает — ellipsis.

---

# 8. Ограничения

```ts
minOptions = 2
maxOptions = 30
titleMaxLength = 60
subtitleMaxLength = 120
```

Если опций меньше 2, spin mode должен показывать ошибку/подсказку, что нужно минимум 2 опции.

# 9. Картинки

Поддержать два способа:

1. Загрузка файла с устройства.
2. Вставка image URL.

Форматы:

```txt
png
jpg
jpeg
webp
```

Для локально загруженных картинок:

* автоматически сжимать;
* максимальный размер изображения: `512x512`;
* целевой формат: WebP;
* quality: `0.82`;
* fallback: JPEG, если WebP недоступен;
* хранение в JSON как data URL.

Image URL:

* хранить как URL;
* не скачивать и не конвертировать в base64.

---

# 10. Share link

Share link нужен для передачи барабана без бэкенда.

Правила:

* ссылка открывает spin mode;
* после открытия share-ссылки конфиг сразу становится локальным;
* предыдущий локальный барабан заменяется без подтверждения;
* картинки в share link не передаются вообще;
* исключаются и локальные картинки, и image URL;
* история в share link не входит.

Технически:

* конфиг для ссылки сериализуется в JSON;
* картинки удаляются из конфига;
* JSON кодируется через UTF-8;
* сжимается через `lz-string`;
* кодируется в base64url-safe формат;
* кладётся в hash URL.

Пример:

```txt
https://example.com/#wheel=...
```

Важно: нельзя использовать простой `btoa(JSON.stringify(...))`, потому что он ломается на Unicode.

Если ссылка слишком длинная:

```txt
maxEncodedConfigLength = 6000
```

Показать ошибку:

```txt
Ссылка слишком длинная. Уменьшите текст или используйте JSON export.
```

# 11. JSON import/export

## Export

* экспортирует полный конфиг;
* включает картинки;
* скачивает `.json` файл;
* JSON версионированный.

## Import

* принимает `.json`;
* сразу заменяет текущий барабан;
* без подтверждения;
* при ошибке показывает понятное сообщение;
* после успешного импорта сохраняет конфиг локально.

Кнопки «Скопировать JSON в буфер» не нужно.

---

# 12. Локальное хранение

Использовать:

* IndexedDB через `idb` — для полного конфига с картинками;
* localStorage — только для лёгких служебных данных при необходимости.

Логика старта приложения:

1. Если URL содержит `#wheel=...`, декодировать его.
2. Сохранить полученный конфиг как локальный.
3. Открыть spin mode.
4. Если URL пустой — загрузить последний локальный барабан из IndexedDB.
5. Если локального барабана нет — загрузить demo wheel.

---

# 13. История выпадений

История нужна.

Требования:

* показывать последний результат под барабаном;
* история раскрывается отдельным блоком;
* хранить последние 10 результатов;
* хранить дату и время;
* хранить локально;
* привязывать к конкретному барабану через fingerprint;
* есть кнопка «Очистить историю».

Историю очищать, если меняются:

* title/subtitle опций;
* количество опций;
* порядок опций.

Историю не очищать, если меняются:

* цвета;
* размеры карточек;
* тема;
* фон;
* цвет стрелки.

# 17. Acceptance criteria

Приложение считается готовым в первой итерации, если:

1. Пользователь может открыть demo wheel и свайпом запустить вращение.
2. Слабый жест не запускает результат.
3. Нормальный жест запускает spin.
4. Барабан останавливается так, что карточка точно центрирована под стрелкой.
5. Последний результат отображается.
6. История последних 10 результатов сохраняется с датой и временем.
7. Пользователь может открыть редактор и изменить опции.
8. Редактор работает как WYSIWYG.
9. Можно загрузить картинку с устройства.
10. Можно задать image URL.
11. Можно экспортировать полный JSON.
12. Можно импортировать JSON.
13. Можно скопировать share link без картинок.
14. Share link корректно открывается на другом устройстве.
15. Кириллица и emoji не ломаются в JSON и share link.
16. Приложение корректно работает на мобильной ширине.
17. `npm run build` проходит успешно.
18. Unit tests проходят успешно.

# Engineering constraints

The app must be built as a modern client-side SPA.

Use:
- React
- TypeScript
- Vite
- CSS Modules
- modern browser APIs
- IndexedDB through `idb`
- URL-safe UTF-8 serialization
- Pointer Events for mouse/touch/stylus input

Do not use:
- Angular
- Next.js
- backend/server code
- Redux/Zustand unless explicitly requested later
- jQuery
- CommonJS
- React class components
- legacy browser support such as IE
- UI kits or design systems

The code should target modern evergreen browsers, with priority on:
- current iOS Safari
- current Android Chrome
- desktop Chrome/Edge/Firefox as secondary targets

Avoid experimental language features unless they are already supported by the chosen toolchain and target browsers.
